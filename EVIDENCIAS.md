# Evidence index (living)

One row per claim or figure used in OE1-OE4, the Capstone and the paper: claim, evidence file, sha256, review status, date. Checked by `python scripts/verify_evidence_index.py` (exit 1 on a missing file or a hash mismatch); `tests/test_verify_evidence_index.py` runs it in the fast suite.

- **Review status** (taken from each evidence file's own header and from the review files, not an opinion of this index): `independent` = a reviewer that did not write it reproduced the numbers in a separate process (still directed by the same team; not a peer review); `self` = written and checked by the executing agent only; `none` = no review statement found. When an independent review asked for corrections, the note column says whether they were applied.
- **sha256**: of the file after CRLF to LF normalisation for text files (Windows `autocrlf` changes working-tree bytes; some hashes frozen inside protocols were taken on CRLF bytes, see `results/revision_independiente_20261107/REVISION.md`, finding C-1). The checker accepts both the normalised and the raw hash.
- **versioned**: `yes` = tracked by git, so a clean clone can verify it. `no` = exists only on the author's disk because `results/` is git-ignored; it is verified when present and reported as SKIPPED otherwise (`--strict-all` makes it fail; `--root <checkout>` points to a checkout that has the file).
- **date**: last commit date for versioned files, file modification date otherwise.
- Not indexed (outside this repo): `Documentos/OBJETIVOS.MD`, the university documents under `C:\universidad`, the Capstone and `ENTREGA_FINAL_*` copies. Add a row when a copy is placed inside the repo.
- Refresh a row only after re-reading the file: `python scripts/verify_evidence_index.py --print-hash <path>` prints the normalised hash.
- Rows marked `G 2026-11-07` were reviewed in `results/revision_independiente_20261107/REVISION.md`.
