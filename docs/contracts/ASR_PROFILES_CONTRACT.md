# `asr_profiles` and the MRCD ASR path (CURRENT implementation, mrcd 0.3.0)

Sources: `mrcd/asr_profiles.py`, `mrcd/extractors/linguistic.py` (`VerbatimASR`), `mrcd/live/streaming_asr.py`, `mrcd/reproducibility.py`, `results/asr_recovery_20261031/PERFIL_P1.md`. Real metadata blocks: `examples/batch_p0.json` and `examples/batch_p1.json` (`metadata.asr_profile`).

Scope note: this is the ASR **inside MRCD** (local Faster-Whisper). It is unrelated to the ASR adapters of the web app (`simulado`, `gestionado`, `whisper_http`, `speechmatics`, `deepgram`, `oratoria_engine`). MRCD never calls them; feeding MRCD with a transcript from another ASR is a distribution shift that has not been measured and is not supported.

## 1. Profiles

|                          | `p0` (default)                                                                                                                                                        | `p1_disfluent_prompt`                                                                                                                             |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| status                   | historical default; parameters pinned by a test against the pre-change call                                                                                           | **EXPERIMENTAL, opt-in, not validated outside DIHANA**                                                                                            |
| differs from p0          | -                                                                                                                                                                     | only `initial_prompt`                                                                                                                             |
| `initial_prompt`         | `eh, este, o sea, mmm, bueno, tipo, ah, este...` (sha256 `bd0bddb4329c6c75e2dd7c0b21366a418cc23314f8155357401a1577853b19fa`)                                          | literal P1 text (sha256 `fe49e930ccc9f94847b7bedaec65f8c347cecaccbcd7283545618bc194c6a8b2`), pinned by a test                                     |
| common decode parameters | `language="es"`, `word_timestamps=True`, `condition_on_previous_text=False`, `suppress_tokens=[]`, `vad_filter=False`, `beam_size=5`, `temperature=0.0` (no fallback) | same                                                                                                                                              |
| chunking                 | `chunk_s=8.0`, `overlap_s=2.0`                                                                                                                                        | same                                                                                                                                              |
| marks in output          | none (historic schema unchanged; additive `metadata.asr_profile` only)                                                                                                | `Event.asr_profile` + `asr_experimental: true`; live rows get the same two keys; result `warning` gets the experimental note and the anomaly note |

Why p1 is experimental (carry this wording): in the exploratory DIHANA experiment a fluent control prompt of equal length and domain did not reproduce the gain observed with P1; a written fluent prompt suppresses repetitions and P1 preserves them; which feature matters (oral vs written register, punctuation, domain overlap, the filler list already present in P0) is not proven. P0 is itself a prompt with a filler list; there is no no-prompt control; one control, one length. The WER improvement (0.153 to 0.130) is equal under the fluent control C1 (0.129) and is **not** evidence of recovery. Downstream models were trained on P0 text and were not retrained for P1.

## 2. Inputs and outputs

|               |                                                                                                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Model         | faster-whisper `small` (Systran snapshot `536b0662742c02347bc0e980a01041f333bce120`, `model.bin` sha256 `3e305921506d8872816023e4c273e75d2419fb89b24da97b4fe7bce14170d671`), int8 on CPU as recorded in the fixtures (`faster_whisper 1.2.1`, `ctranslate2 4.8.2`) |
| Input         | mono float32 16 kHz array (the engine validates it before the ASR is called)                                                                                                                                                                                       |
| Output        | `list[Word]`: `text` (as emitted), `norm`, `start`, `end` (s), `prob`, `punct_after` (`linguistic.py:27`). Words with empty `norm` are dropped                                                                                                                     |
| Normalisation | `normalize()`: lowercase, NFKD, strip accents, keep `[a-zñ- ]`, trim hyphens/spaces. Used for features and loop/echo detection; the transcript shown to users is the raw text joined by spaces                                                                     |

| Timestamps    | Whisper word timestamps; absolute seconds after chunk offsetting. Word times of the same words differ between streaming and offline decodes (median 0.01-0.66 s on 8 clips, `PARIDAD_LIVE_V2.md`)                                                                  |

## 3. Chunking (batch path) and streaming (live path)

- `transcribe_chunked(audio, chunk_s=8, overlap_s=2)` (`linguistic.py:168`): audio of at most `chunk_s` is decoded in one pass. Otherwise chunks of 8 s every 6 s; from each chunk after the first, only words whose **midpoint** is at or after the 2 s overlap are kept (deduplication by region, not by text, so a real "la la" survives). A chunk shorter than 1 s is skipped, so **a tail of less than 1 s is not transcribed** (`if len(seg) < SAMPLE_RATE: break`).
- `asr_chunk_s=0` decodes the whole file in one pass and loses repetitions (Whisper "corrects" toward prose): measured in `results/asr_chunk_study.md`. Short chunks also create false repetitions at seams (about 47 % of new repetitions at 8 s cross a chunk boundary vs 6.9 % at baseline, `results/repetition_audit.md`).
- Live path (`StreamingASR.merge_recent`): every tick re-transcribes the last 13 s (`CONTEXT_S + WINDOW_S`) in one pass and merges the words by absolute time (`dedupe_words`, tolerance 0.12 s, keeps the higher `prob`). **This is not equivalent to the batch path**: 13 s in one decode vs 8 s chunks. Measured disagreement 0.76 pooled word-error between the two outputs on 8 clips (a disagreement between two ASR outputs, not an accuracy WER; no human reference exists for those clips). Do not call it "WER" without a human reference.

## 4. Recovery and anomaly detection (reported, never filtered)

`detect_asr_anomalies(text, prompt)` runs on every transcript and writes `metadata.asr_profile.anomalies`:

| kind                     | rule                                                                                                                                | known limits                                                                                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `prompt_echo`            | at least 4 consecutive prompt tokens appear AND that n-gram holds at least 2 distinct non-function words                            | false positives on in-domain phrases that overlap the prompt; false negatives on echoes of function words only and on hallucinations unrelated to the prompt |
| `repeated_ngram_loop`    | n-gram of 1-4 tokens repeated back to back at least 5/4/4/4 times, also after dropping vocalised fillers (`skipping_fillers: true`) | loops interleaved with other words are not detected; "eh" x5 does flag                                                                                       |
| `high_compression_ratio` | zlib ratio > 2.4 on text of at least 80 characters                                                                                  | the 80-character minimum is an invention of the module                                                                                                       |

It is a **heuristic**; thresholds are conventions, not calibrated. The transcript is never modified. Events derived from flagged words are unreliable (the `warning` says so, only for non-default profiles). "ASR recovery" as an experiment (`mrcd/asr_recovery/`, exploratory) is a research kit, not part of the engine path.

## 5. Selection, fingerprint, failures

- Selection: `DisfluencyEngine.load(..., asr_profile="p0"|"p1_disfluent_prompt")` or `VerbatimASR(profile=...)`. No environment variable. Unknown names raise `ValueError` before any model is loaded. A custom `ASRProfile` must have `experimental=True` unless it equals p0, and cannot reuse a registered name with different parameters.
- Fingerprint: `metadata.asr_profile.asr_fingerprint.profile_fingerprint` = sha256 of `{schema:1, profile, prompt_sha256, decode params, chunk_s, overlap_s, model.bin sha256, compute_type, device, OMP threads, audio sha256}`; namespace `<name>-<prompt sha12>`. **The engine has no ASR cache**; the fingerprint is the key a cache added by an integrator must use. `asr_cache.key` is a deprecated alias (`engine_cache: null`). With `model_bin_sha256 = null` the fingerprint contains no model identity beyond `compute_type/device`.
- Environment: decode text depends on `OMP_NUM_THREADS`; it must be in the environment **before numpy is imported** (the engine warns, it does not change the environment). "Bit-identical" decodes hold only on an unloaded machine with `OMP_NUM_THREADS=4`; two concurrent slow suites produced 6 failures each. `omp_effective_verified` may be `null` (not verified).
- Failures: CUDA libraries missing -> falls back to CPU int8 and prints `[asr] GPU no utilizable ...` to stdout (observed while generating the fixtures: `cublas64_12.dll` not found). `model_info()` cannot resolve/hash `model.bin` -> logged and exposed as `model_info_error`; the run continues. An ASR object without `.profile` -> `profile: "unknown"`, `experimental: null`. First load needs the model in the local Hugging Face cache; without network the process may stall on hub checks unless `HF_HUB_OFFLINE=1` is set (observed while generating the fixtures; root cause not investigated).
- Dependencies: `faster-whisper`, `ctranslate2`, `silero-vad` (core dependency of the acoustic extractor; `extract_acoustic` falls back to an energy VAD when it is not used, `acoustic.py:113-119`), `librosa` (pYIN), `torch`; no network call is made by MRCD code at inference.

## 6. Tests

`tests/test_asr_profiles.py` (p0 kwargs pinned, p1 only differs in prompt, hash pinned, unknown profile rejected, fingerprint differs between profiles and depends on prompt hash and `chunk_s`, anomaly cases including known false negatives/positives, events marked for p1 and not for p0, `unknown` profile, live rows marked), `tests/test_asr_chunking.py` (repetition preserved, no duplication across overlap, absolute monotone timestamps, short-audio fallback, chunk 0 disables), `tests/test_reproducibility.py`, `tests/test_omp_*`.

## 7. What is NOT measured

WER of any profile against a legitimate human reference outside DIHANA folds 1-4 (fold 5 is historical and must not be used for tuning); behaviour on app audio (16 kHz PCM16 160 ms chunks with echo cancellation, noise suppression and AGC on); streaming-vs-offline accuracy on the same human-referenced units. These are open items for OE3, not statements of this contract.
