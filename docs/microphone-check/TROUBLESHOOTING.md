# Microphone check - troubleshooting

Every item below is a diagnosis procedure, not a claim that it was observed. No physical microphone has been run by the authors.

| Symptom                                                                              | Likely cause                                                                                                    | What to do                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `RuntimeError: No se pudo abrir un micrófono mono a 16000 Hz ...` plus a device list | No input device, device busy (exclusive mode), privacy permission off, or the driver refuses mono 16 kHz        | 1) Check README step 2 (permissions). 2) Close apps using the mic. 3) Pick an index from the printed list: `--device 3`. 4) Windows Sound > Input > device properties > Advanced: turn "Allow applications to take exclusive control" OFF; set the format to 1 channel, 16000 Hz or higher (whether the Windows host API converts to 16 kHz for you is not verified here; try another host API entry from the list). |
| `checks.signal` FAIL: "no signal" and `peak_dbfs` around -120                        | Muted device, wrong device, or Windows blocked microphone access (it can deliver pure silence without an error) | Check the Windows input bar moves when you speak; turn on Privacy > Microphone for desktop apps; select the right device with `--device`.                                                                                                                                                                                                        |
| `clipping` FAIL/WARN                                                                 | Input gain too high or speaking too close                                                                       | Lower the input volume in Windows Sound > Input; keep 15-30 cm.                                                                                                                                                                                                                                                                                  |
| `level` WARN (peak below -30 dBFS)                                                   | Gain too low, too far, wrong device (laptop array far away)                                                     | Raise input volume, move closer.                                                                                                                                                                                                                                                                                                                 |
| `noise_floor` WARN/FAIL                                                              | Fan, air conditioner, music, open window, noisy USB hub                                                         | Change room, turn off the noise source, use a closer microphone. A noisy floor degrades the ASR.                                                                                                                                                                                                                                                 |
| `silence_edges` WARN                                                                 | You started speaking before the prompt, or kept talking after the last prompt                                   | Repeat and follow the console prompts (silent for the first 5 s and the last 5 s).                                                                                                                                                                                                                                                               |
| `dropped_blocks` WARN/FAIL                                                           | CPU overload (Whisper on CPU), USB power saving, Bluetooth dropouts                                             | Close heavy apps, plug the laptop in, use a wired mic, avoid Bluetooth. Compare with a `--simulate-wav` run: if the simulation has 0 drops but the mic drops blocks, it is the driver/hardware.                                                                                                                                                  |
| `clock_drift` WARN                                                                   | Dropped blocks (timeline shortened) or the process was starved                                                  | Same as above. Note that the default live config does not fill dropped blocks with zeros.                                                                                                                                                                                                                                                        |
| `[asr] GPU no utilizable ... usando CPU int8`                                        | CUDA libraries missing                                                                                          | Not an error: it falls back to CPU. The run is slower; keep the machine idle.                                                                                                                                                                                                                                                                    |
| First rows only appear after ~7-10 s                                                 | Expected warm-up: a window needs 3 s of context plus the right margin                                           | Not a fault.                                                                                                                                                                                                                                                                                                                                     |
| `consent required: run interactively ...`                                            | The script was started without a terminal                                                                       | Run it in a normal terminal, or pass `--i-consent` after reading CHECKLIST.md.                                                                                                                                                                                                                                                                   |
| `checkpoint not found`                                                               | Wrong working directory                                                                                         | Run from `C:\zArnes-tesis\mrcd` (see README step 3).                                                                                                                                                                                                                                                                                             |
| Run folder already exists                                                            | Two runs started within the same second                                                                         | Run again; the script never overwrites a folder.                                                                                                                                                                                                                                                                                                 |
| Whisper model download attempt / no network                                          | The small model is not in the local cache                                                                       | The kit does not download anything; the model must already be cached (it is, for the official engine setup).                                                                                                                                                                                                                                     |
| `error` not null in `share_summary.json`                                             | Worker crashed while scoring                                                                                    | Read `run.log` (it never contains transcript text). Send `run.log` + `share_summary.json`.                                                                                                                                                                                                                                                       |

## Safe diagnosis without exposing private speech

- Always diagnose from `share_summary.json`, `level_report.json` and `run.log`. They contain numbers and class names only.
- If you must listen to a problem recording, create it with `--keep-audio` on a neutral text, listen locally, and delete
  `session.wav` afterwards. Never attach it to a message or a repository.
- To separate "hardware/driver problem" from "software problem", run the same command with
  `--simulate-wav <existing clip>`: it goes through the same metering and engine code without touching the microphone.
