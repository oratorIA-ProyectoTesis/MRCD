## D1. P1 words: fresh decode instead of reuse (protocol section 3, applied)
Protocol section 3 requires re-decoding a reused P1 source whose word text differs from Plan B's P1 on the common turns. A first evaluation run (2026-11-08, 15:29 UTC, git head 83a8d7e) used the reused P1 decodes. The reuse proof then showed 772 identical texts of 827 common turns (`p1_reused_vs_plan_b_p1`), so P1 was decoded fresh for all 983 turns (`scripts/plan_f/decode_p1.py`, same `transcribe_chunked(asr, audio, "P1")` path, CPU int8, `OMP_NUM_THREADS=4`, ctranslate2 seed 13 per turn). All primary P1 figures (`p1_rule`, `p1_text`, HF1) use the fresh decode. The reused-P1 result is kept as a labelled sensitivity (`p1_rule_reused`, `sensitivity_ft_rule_minus_p1_rule_reused`). The first run's JSON was kept outside git; its HF1 delta was +0.191 versus +0.185 in the final run (same verdict: supported). The final run did not change any conclusion.

## D2. Residual non-identity versus Plan B decodes
Fresh P1 vs Plan B P1: 820 of 827 common turns have identical text (786 identical text and word times). FT (this plan's `ft_small_v1` path) vs Plan B FT_best: 921 of 983 turns have identical text (743 identical text and word times). The protocol expected equal text and says differences are reported, not hidden. Not investigated further; possible causes (not tested): different decode batching or thread scheduling, a machine shared with the working session (the decode wall-clock RTF is flagged as such in RESULTS_F.md), and differences between the Plan B script path and the service profile path. The primary results use the fresh decodes as the protocol states.
