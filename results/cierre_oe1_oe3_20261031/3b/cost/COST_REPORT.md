# Computational cost (Task 3.4)

Self-reviewed by the author. CPU-only, serial, OMP_NUM_THREADS=4 pinned before numpy, `HF_HUB_OFFLINE=1`.
Full per-file table and raw data: `COST_REPORT_tables.md` (generated by `scripts/cierre3b/reports.py cost`), `cost_runs.json`, `video_cost.json`.
Machine: Intel i7-13650HX (14 cores / 20 threads), 23.7 GB RAM, Windows 11, torch 2.9.1+cpu, faster-whisper small int8. Background system CPU 3-8 % during the cost rounds (nothing heavy running). An earlier trial of the live study ran while a game used 35-40 % CPU; that trial was discarded and every number reported here comes from runs on the idle machine.

## Sample
13 inputs, plain slices of real local recordings (`data/annotation_batch_01`, 16 kHz mono PCM16): 5, 9, 13.5, 17, 22, 25.8, 27.2, 33.6, 36, 43.2, 47, 51 and 60 s.
The 5 s and 9 s files are rejected by the engine (it needs >= 13 s: `audio_too_short`; rejection costs < 1 ms). Coverage 11/13 analysable, 0 schema errors in the 11 documents, staged events equal `engine.analyze` on all 11.
1 discarded cold round + 3 measured rounds; values are median (min-max).

## Findings
* Full pipeline as measured (both ASR profiles + Vc head, i.e. everything): RTF about 1.0 (0.93-1.07; 1.85 for the 13.5 s file, see below). The default path (p0 + V0 only) costs RTF 0.45-0.51, about 0.5 s of compute per second of audio (a 60 s file takes about 30 s). The service end to end (`MrcdAnalyzer.analyze_bytes`) agrees: RTF 0.49-0.50.
* ASR dominates: p0 median RTF 0.44, p1 0.53. Acoustic/prosodic features (Silero VAD + pYIN) 0.039; checkpoint forward (V0) 0.0015; Vc head extra 0.0014; linguistic windows, decision and report generation each < 0.001 (report plus schema validation about 10 ms). Load/prep < 1 ms.
* Content-dependent outlier: for `c13s` the p0 ASR took 16.2 s for 13.5 s of audio (RTF 1.2, stable across rounds) against about 0.45 for the others. Not diagnosed; cost is not strictly proportional to duration.
* CPU time / wall time about 3.9 (the 4 OMP threads are fully used). Memory: 562 MB after loading the models, about 800 MB during a run, process peak working set 1.15 GB.
* Cold start (checkpoint + Whisper small + Vc head from local files): 1.5 s wall (3.2 s CPU), reported apart. The first pass (round 0) was not slower than the warm rounds (34.4 s vs 33.6 s median per file), so the first-run penalty is the model load.
* Live (per tick, acoustic path only, from the 3.3 study on the idle machine): 0.17-0.20 s median per 0.5 s tick, p95 0.26-0.28 s, about one core; a 10.5 min session consumes 3.3-3.9 min of CPU.
  The per-tick ASR is NOT in that number: the streaming ASR re-decodes the 13 s ring and measured RTF 0.96-1.29 at a 2 s tick (RTF 3.3 at a 0.5 s tick on 8 units), so a 0.5 s tick with ASR does not fit one CPU session on this hardware; a 2 s ASR tick is about real time.
* Video (separate modality): 4 local mp4 clips (22-28.5 s, 480x480, 10 fps): decoding alone about 0.08 s per clip; decoding + MediaPipe FaceLandmarker (VIDEO mode, CPU) 1.9-2.5 s per clip, 6.6-7.7 ms per frame, RTF about 0.09; a face was found in 98.6-100 % of frames. A non-existent file is reported `available: false` with its reason, never 0.
  **Not measured and not claimed: audio/video fusion, speaker identity, synchrony.** The service declares `kinesic_video` unavailable. DIME AVI files are screen recordings without faces and were not used; the mp4 clips are not tied to a verified speaker.
* The microphone check was NOT run and nothing here quantifies it.
