## What the section shows (and refuses to show)

Per event: class (Spanish label plus the internal key), start-end in seconds ("franja de decisión", not a human boundary), the
model score with the label **no calibrado** (never a percentage), n windows, "Experimental" and "Salida técnica sin validar"
badges (for `block`, `rhetorical_pause`, `neutral_pause`, `revision`, following `docs/contracts/APP_INTEGRATION_CONTRACT.md`
B.6 rule 3). Provenance: checkpoint file and short sha256, ASR profile, head (`ninguna (V0)` by default), window plan,
contract version. Warnings from the engine are listed. Missing measures and modalities render **"No disponible: reason"**;
`events_per_minute` is always shown next to the audio duration. There is no "uncertain" state, no emotion, anxiety, doubt or
diagnosis wording, and the visual channel is declared unavailable (the service receives audio only).

## Known divergences from `docs/contracts/APP_INTEGRATION_CONTRACT.md` (read before applying)

1. The contract proposes that the **app backend** is the producer and the browser never talks to MRCD. This patch adds a
   **browser-direct, development-only** path (user picks a WAV; CORS must be enabled on the dev server). It exists because the
   app keeps no session audio today (it streams 160 ms chunks and retains none), so a session-bound flow needs the owner decision
   in contract B.8 (temporary PCM buffering) that nobody has made. `DisfluencyAnalysisView` only consumes a validated
   `mrcd.analysis/v1` document, so a future backend-fed report reuses it unchanged; the direct client and the file picker are
   the parts to drop at that point.
2. The patch does not implement the session binding (`oratoria.mrcd-binding/v1`), gap handling or the
   `oratoria.mrcd-report/v1` record; it shows the analysis of the picked file only, not tied to the report's session.
3. Browser DSP and linear resampling effects on the checkpoint are not addressed (a picked WAV avoids them; the live path would not).
